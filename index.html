Security & data handling

Know exactly where your data goes.

A plain answer for your security review, component by component.

Where each LogLens component runs and what, if anything, leaves the host
Component Where it runs What leaves the host
Parsing & detectionOn the host, as the invoking userNothing
Warm daemonUnix socket (0600, per user) or loopback TCP with a random token on WindowsNothing, localhost only
Neural model (--deep)Bundled with native installs; local directory via LOGLENS_MODEL_DIRNothing, runs offline
AI root-cause & askOnly when you pass --rca or use askOpt-inAnomaly summaries to your chosen provider. The report shows the count sent and token usage.
AlertsOnly when you configure an alerter in the SDKOpt-inThe alert message, to the Slack, Teams or email destination you set.

Deployment

Deploys like any other system package.

Native installers bundle neural mode, need no Python, and update through the channel you already patch with.

Debian / Ubuntu
$ curl -1sLf 'https://dl.cloudsmith.io/public/loglensai/loglensai-363o/setup.deb.sh' | sudo -E bash
$ sudo apt install loglens
Fedora / RHEL
$ curl -1sLf 'https://dl.cloudsmith.io/public/loglensai/loglensai-363o/setup.rpm.sh' | sudo -E bash
$ sudo dnf install loglens
Homebrew (Apple Silicon)
$ brew install loglensai/tap/loglens
winget
> winget install LoglensAI.LogLens
pipx (Python 3.10+), with optional neural extra
$ pipx install loglensai
$ pip install "loglensai[deep]"
Multi-arch image (amd64 + arm64)
$ docker run --rm -v "$PWD:/data" loglensai/loglens analyze --source app.log

Updates: apt upgrade, brew upgrade, winget upgrade or pip install -U loglensai.

Runs as a managed service

Native installs register the warm daemon with systemd, launchd or Windows. If it is ever down, the CLI silently runs in-process with identical output.

$ systemctl --user status loglens
$ loglens daemon status

Gates your pipelines

Stable exit codes, JSON output and an official GitHub Action with job summaries and annotations.

0Success, no gate tripped
1Error: bad source, model or input

Questions from IT leaders

The short answers.

Does any of our log data leave our servers?+

Not for detection. Logs are read, parsed and analyzed on the host. Only if you turn on AI root-cause or ask does LogLens send anomaly summaries, never the full log, to the LLM provider you configure. The report tells you how many summaries were sent and the token usage.

Can it run in an air-gapped environment?+

Yes. Native installs bundle the neural model, so even deep mode runs fully offline. For pip installs, point LOGLENS_MODEL_DIR at a local model directory.

What does it cost?+

The Individual edition is free under the MIT license, with no per-GB or per-host fees. Team and Enterprise are in development; pricing will be announced at launch. Join the waitlist to hear first.

How is it installed and kept up to date?+

Through your normal package manager: apt, dnf, Homebrew or winget, plus pipx and a Docker image. Updates arrive through the same channel, and the installer registers the warm daemon as an OS service.

Could it disrupt our existing scripts or CI?+

It is designed not to. Exit codes are fixed (0, 1, 2), JSON output is machine-readable, and if the daemon is unavailable the CLI falls back to running in-process with identical results.

Can we audit the code?+

Yes. The full source is public on GitHub under the MIT license.

Who builds and supports LogLens?+

LogLens is built by Paras Rajput. Today, support is through GitHub Issues. Priority and SLA-backed support are planned for Team and Enterprise.
