01Concepts#

LogLens treats logs as an anomaly-detection pipeline, not a grep:

  1. Parse - read logs from a file, URL, stdin, or a live command; detect the format; extract timestamp, level, service, and message.
  2. Template extraction - collapse near-identical lines into templates (e.g. connection refused host=<*>), so 10,000 identical errors become one incident with a count.
  3. Represent - turn templates into vectors: TF-IDF (fast/turbo) or neural embeddings (deep).
  4. Detect - cluster with DBSCAN and score each entry 0-1 using a single scoring policy (severity, rarity, failure keywords, flood, timing).
  5. Group - merge related anomalies into incident families.
  6. Explain - every anomaly carries a score and human-readable reasons.
  7. Deliver - terminal, JSON, live monitoring, alerts, or an offline HTML report.

Anomaly score: a number in [0, 1]. Higher = more anomalous. Severe levels (FATAL/CRITICAL) are "hard-flagged" but still ranked so you can tell a kernel panic from a bare FATAL.

Incident family: a group of anomalies that share a template/service, shown with an occurrence count (×N) and a max score.

02Installation#

LogLens installs as a self-contained binary (no Python needed) with neural mode built in and a warm daemon that auto-starts. See INSTALL.md for the full per-OS guide. Summary:

PlatformCommand
Debian/Ubuntucurl -1sLf 'https://dl.cloudsmith.io/public/loglensai/loglensai-363o/setup.deb.sh' | sudo -E bash then sudo apt install loglens
Fedora/RHELcurl -1sLf 'https://dl.cloudsmith.io/public/loglensai/loglensai-363o/setup.rpm.sh' | sudo -E bash then sudo dnf install loglens
macOS (Apple Silicon)brew install loglensai/tap/loglens
Windowswinget install LoglensAI.LogLens (or Scoop)
Python (any OS)pipx install loglensai - add neural with pip install "loglensai[deep]"
Dockerdocker run --rm -v "$PWD:/data" loglensai/loglens analyze --source app.log

Updating: native installs update through the normal channel (sudo apt upgrade, brew upgrade, winget upgrade); pip via pip install -U loglensai.

Requirements (pip): Python 3.10+. Neural mode needs the [deep] extra (sentence-transformers + torch); it's already bundled in the native installers.

03Quick start#

bash
loglens analyze --source app.log  # fast, general-purpose
loglens analyze --source huge.log --turbo  # parallel scan for big files
loglens analyze --source app.log --deep  # neural (semantic) detection
loglens analyze --source app.log --html report.html # offline HTML report
loglens watch "docker logs -f my-api"  # live monitoring
loglens ask "why did db-service degrade?" --source app.log  # natural-language Q&A (LLM)
loglens analyze --source build.log --format json --fail-on error  # CI/CD gate
loglens daemon start  # keep it warm for instant runs

04Global usage & conventions#

loglens [OPTIONS] COMMAND [ARGS]...
  • loglens --help / loglens -h - list all commands.
  • loglens help - same as --help (a real subcommand).
  • loglens COMMAND --help - flags and examples for that command (the top-level help lists commands only; each command's flags live here).
  • loglens version - installed version.

The --source value accepts:

  • a file path - --source /var/log/app.log
  • a URL - --source https://example.com/app.log (downloaded, then analyzed)
  • stdin - cat app.log | loglens analyze --source -

Piping: LogLens exits cleanly when piped to a consumer that closes early (e.g. loglens analyze --source app.log | head) - no broken-pipe traceback.

05Detection modes explained#

ModeFlagHow it worksUse it when
Fast(default)TF-IDF clustering + timing + severity + keywordsEveryday analysis; balanced speed/accuracy
Turbo--turboMultiprocess byte-range scan + template dedup; unsupervised, count-based; skips embeddings, timing, and the modelVery large files where you want throughput
Deep--deepNeural (MiniLM) semantic embeddings + TF-IDF blendSubtle, semantically-worded anomalies

Notes:

  • Turbo counts differ from the default (supervised) run by design - turbo is a fast approximation. Drop --turbo for the model's verdict.
  • Fast/Deep use a bundled supervised model by default (trained on infra logs) unless you pass --no-model or your own --model.
  • All three share the same 0-1 scoring policy and reason vocabulary, so scores are comparable and rankable.

06Commands reference#

analyze

Analyze a log source for anomalies. This is the primary command.

loglens analyze --source <path|url|-> [OPTIONS]

Options (defaults in brackets):

FlagDefaultDescription
--source <str>(required)Log source: file path, URL, or - for stdin.
--turbooffFast multiprocess scan for huge files (byte-range + template dedup). Unsupervised; skips embeddings, timing, and the model.
--deepoffUse neural (transformer) embeddings - more accurate on semantic anomalies, slower. Needs the [deep] extra (bundled in native installs).
--workers <int>4Number of parallel workers (used by turbo and parallel stages).
--limit <int>20Max anomaly families to display in the terminal.
--sort-by <str>severitySort anomalies by severity, time, or service.
--model <path>(none)Use a supervised model from loglens train instead of the raw threshold.
--no-modeloffIgnore the bundled default model - pure unsupervised detection.
--explain <int>0Show the top-N scored entries (flagged or not) with score + reasons. For debugging near-misses/thresholds.
--dry-runoffStop after ingestion and show stats only (no detection). Great for checking parsing/format.
--verboseoffShow a sample parsed entry (see how a line was parsed).
--format <str>terminalOutput format: terminal (human) or json (machine-readable, for CI/CD).
--fail-on <level>(off)Exit non-zero (code 2) if any anomaly is this severity or worse: critical | error | warning | fatal | emergency | any. For gating CI/CD builds.
--html <path>(none)Save a standalone offline HTML report (e.g. report.html). Includes RCA if --rca is set.
--rcaoffRun AI root-cause analysis on the detected anomalies (needs an LLM key - see §9).
--provider <str>(env)LLM provider for --rca: openai | azure | groq (or LOGLENS_LLM_PROVIDER).
--llm-model <str>(env)LLM model / Azure deployment name (or LOGLENS_LLM_MODEL).
--api-key <str>(env)LLM API key. Prefer the env var LOGLENS_LLM_API_KEY over the flag.
--rca-out <path>(none)Save the RCA narrative to a markdown file.

Examples:

bash
# Everyday
loglens analyze --source app.log
# Huge file, throughput-first
loglens analyze --source big.log --turbo --workers 8
# Neural detection, show top 50 families sorted by time
loglens analyze --source app.log --deep --limit 50 --sort-by time
# Debug why a line wasn't flagged - show top 30 scored entries with reasons
loglens analyze --source app.log --explain 30
# Pure unsupervised (ignore bundled model)
loglens analyze --source app.log --no-model
# Use your trained model
loglens analyze --source app.log --model loglens-model.pkl
# Offline report + AI root cause
loglens analyze --source app.log --rca --html report.html
# CI/CD: machine-readable + fail the build on ERROR-or-worse
loglens analyze --source build.log --format json --fail-on error

Terminal output includes: source + detected format, read → parsed line counts, the mode + its signals, anomaly families (each with level, service, ×N count, score, sample, and ↳ why: reasons), a severity breakdown, and an ⚠ INCIDENT flag when ≥30% of entries are severe.

watch

Run a command and analyze its output live, flagging anomalies as they stream.

loglens watch "<command>" [OPTIONS]
FlagDefaultDescription
<command>(required)The command to run and watch, e.g. "docker logs -f my-api".
--window <int>500Rolling window size (number of entries kept for context/rescoring).
--mode <str>fastDetection mode: fast or deep.
--sensitivity <str>normallow, normal, or high - how eagerly to flag.
--threshold <float>(auto)Explicit flag threshold, overrides sensitivity.
--quietoffOnly print anomalies (no status line).
--rcaoffAfter you stop it (Ctrl-C), run AI root-cause on everything caught.
--rca-out <path>(none)Also save that RCA as markdown.
--html-report <path>(none)After stopping, write a shareable HTML dashboard of the session.

Examples:

bash
loglens watch "docker logs -f my-api"
loglens watch "tail -f /var/log/app.log" --sensitivity high --quiet
loglens watch "kubectl logs -f deploy/api" --rca --html-report session.html

Stop with Ctrl-C; any --rca/--html-report runs on exit.

ask

Ask a natural-language question about a log. Detects anomalies, then sends only anomaly summaries (never the full log) to an LLM for an answer. Requires an LLM key.

loglens ask "<question>" --source <path> [OPTIONS]
FlagDefaultDescription
"<question>"(required)e.g. "why did the payment service start timing out?"
--source <str>(required)Log source: file path.
--deepoffUse neural embeddings for the detection step.
--provider <str>(env)openai | azure | groq.
--llm-model <str>(env)Model / Azure deployment name.
--api-key <str>(env)LLM API key (prefer LOGLENS_LLM_API_KEY).

Example:

bash
export LOGLENS_LLM_PROVIDER=openai
export LOGLENS_LLM_API_KEY=sk-...
loglens ask "what caused the spike in 5xx errors?" --source app.log

train

Train a supervised model on labeled logs, to use later with analyze --model.

loglens train <dataset> [OPTIONS]
FlagDefaultDescription
<dataset>(required)Path to a labeled log file to learn from.
--out, -o <path>loglens-model.pklWhere to save the trained model.
--format <str>bglLabel format: bgl | jsonl | labeled.
--limit <int>(all)Max lines to load.
--no-cvoffSkip cross-validation (faster, but no accuracy estimate).

Example:

bash
loglens train my_labeled.log --format jsonl -o my-model.pkl
loglens analyze --source new.log --model my-model.pkl

Label formats:

  • bgl - the BGL public dataset convention (first token - = normal, else anomaly).
  • jsonl - one JSON object per line with a label field.
  • labeled - a simple labeled text format.

benchmark

Measure detection accuracy (precision / recall / F1) on a labeled dataset.

loglens benchmark <dataset> [OPTIONS]
FlagDefaultDescription
<dataset>(required)Path to a labeled log file.
--format <str>bglLabel format: bgl | jsonl | labeled.
--limit <int>(all)Max lines to load.
--gridoffGrid-search over feature_weight × threshold to find the best config.
--supervisedoffAlso train + evaluate the supervised (RandomForest) head.
--min-f1 <float>(none)Fail (exit 1) if baseline F1 is below this - for accuracy gates in CI.

Example:

bash

bench

Measure processing speed / throughput across modes on a log file (this is about performance, not accuracy - contrast with benchmark).

loglens bench <source> [OPTIONS]
FlagDefaultDescription

--modes <str>fast,turboComma-separated modes to time: any of fast,deep,turbo.

--out <path>(none)Write the results as a markdown table to this file.

Example:

bash

daemon

Manage the resident warm process. See §7 for what it does.

loglens daemon <start|stop|status|restart> [OPTIONS]

daemon start

FlagDefaultDescription
--foreground, -foffRun in this terminal (blocks). Without it, starts detached in the background.
--idle-timeout <int>1800Shut down after this many seconds with no requests. 0 = never (used by the systemd/launchd service).
bash

loglens daemon start -f --idle-timeout 0  # foreground, never idle-exit (service mode)

bash

loglens help  # lists all commands (same as `loglens --help`)

07The warm daemon#

Importing the ML stack (scikit-learn) costs ~1.7 s on every run, even warm. The daemon pays that once and serves analyses over a local socket, so each loglens analyze becomes a sub-second round-trip.

  • Speed: a warm run drops from ≈2.4 s to ≈0.33 s (~7× faster).
  • Identical output: it runs the exact same command with a captured console - same results, same JSON, same exit codes.
  • Safe fallback: if the daemon is down, unreachable, or a different version, the CLI silently runs in-process - behavior never regresses.
  • Transport & security: Unix domain socket on Linux/macOS (0600, per-user); loopback TCP + a random token on Windows. Never leaves localhost; runs as you.
  • Lifecycle: idle-shuts-down after 30 min by default (--idle-timeout).

On/off:

  • Native installs (frozen binaries): daemon is on by default, and the installer registers it as an OS service (systemd user unit / launchd / Windows).
  • pip installs: off by default - enable with LOGLENS_DAEMON=1 or loglens daemon start. Force off anywhere with LOGLENS_DAEMON=0.
bash
# Linux systemd (installed by the package)
systemctl --user status loglens
systemctl --user start loglens
systemctl --user disable loglens  # opt out of autostart

08CI/CD integration#

Two building blocks make LogLens a build gate:

  • --format json - machine-readable output (parse it in any pipeline).
  • --fail-on <level> - exit code 2 if any anomaly is that severity or worse, so the build fails on real incidents.
bash
# Fail the job on any ERROR-or-worse anomaly in the build log
loglens analyze --source build.log --format json --fail-on error

JSON shape:

json
{
  "version": "0.12.x",
  "source": "build.log",
  "mode": "fast",
  "lines_read": 5000,
  "lines_parsed": 4998,
  "incident": true,
  "anomaly_count": 3,
  "anomalies": [
    {"level": "ERROR", "service": "db", "score": 0.95, "count": 3,
     "message": "connection refused | host=db-1",
     "reasons": ["severity ERROR", "failure keyword"]}
  ]
}

GitHub Action (official):

yaml
- uses: LoglensAI/LogLens-AI@v0.12.1
  with:
    source: build.log
    fail-on: error  # critical | error | warning | fatal | any
    mode: fast  # fast | turbo | deep

It posts a job summary (incident table), inline annotations, and fails the job via fail-on. Use if: always() on the step so it runs even when the build step failed - that's exactly when you want the root cause surfaced.

09AI root-cause analysis (LLM)#

Optional. LogLens detects locally, then sends only anomaly summaries (never the full log file) to an LLM for a root-cause narrative. Used by analyze --rca, watch --rca, and ask.

Configure via env vars (preferred) or flags:

bash
export LOGLENS_LLM_PROVIDER=openai  # openai | azure | groq
export LOGLENS_LLM_MODEL=gpt-4o-mini  # or your Azure deployment name
export LOGLENS_LLM_API_KEY=sk-...
loglens analyze --source app.log --rca --rca-out rca.md

Privacy: the report tells you exactly how many anomaly summaries were sent and the token usage. The full log never leaves your machine.

10Python SDK#

python
import loglens
# One-shot analysis
result = loglens.analyze("app.log")  # or a list of lines
for a in result.anomalies:
    print(a.level, a.service, a.score, a.message, a.reasons)
# Streaming / custom pipelines
from loglens import LiveDetector
det = LiveDetector(window=500, mode="fast", sensitivity="normal")
for line in my_stream():
    for anomaly in det.push(line):
        handle(anomaly)
# App self-alerting (logging handler)
from loglens import LogLensHandler
import logging
logging.getLogger().addHandler(LogLensHandler())

Public API includes analyze, analyze_async, analyze_entries, AnalysisResult, Anomaly, LiveDetector, LogLensHandler, Monitor, init, and the alerters (SlackAlerter, TeamsAlerter, EmailAlerter, AlertDispatcher). Import them lazily from the top-level loglens package.

12Exit codes#

CodeMeaning
0Success (no gate tripped).
1Error (bad source, model load failure, invalid input) - also benchmark --min-f1 below threshold.
2--fail-on gate tripped: an anomaly met/exceeded the threshold severity. Use this to fail CI builds.

13Privacy & data handling#

  • Detection is 100% local. Logs are read, parsed, and analyzed on your machine; nothing is uploaded.
  • The daemon is local-only (Unix socket / loopback TCP), runs as you, and can only read files you already can.
  • AI features are opt-in. Only when you pass --rca/--ask does LogLens send anomaly summaries (not the full log) to the LLM provider you configured.
  • Native installs bundle the neural model, so --deep runs fully offline.

loglens: command not foundOpen a new shell so PATH reloads; for tarball installs ensure /usr/local/bin is on PATH.

--deep says sentence-transformers missing (pip)pip install "loglensai[deep]". Native installs already include it.

A line wasn't flagged and you expect it to beloglens analyze --source x.log --explain 30 to see scores + reasons for the top entries.
Check how a line is parsedloglens analyze --source x.log --dry-run --verbose.
